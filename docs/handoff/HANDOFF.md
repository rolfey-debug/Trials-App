# Handoff: AGnVET Trial Work — field trials mobile app

## Overview
A mobile-first app for AGnVET Services (IK Caldwell) small-plot trial work: **spray** (mixing checklists, spray order, conditions records, issue logging), **assess** (GPS-assisted plot-by-plot scoring of diseases/weeds/crop measures, photos, voice), and **present** (field-day walk mode, reports, exports). The core promise: *stand in a plot and the app knows which one* — GPS surfaces the nearest trial and checks the assessor's row while auto-advancing along a walk order.

Primary users: trials coordinators/agronomists and assessors. Secondary: growers (own site only) and chemical-company reps (limited, coded view).

## About the Design Files
The files in `design/` are **design references created in HTML** (interactive prototypes showing intended look and behavior), not production code. They use a proprietary streaming-component format (`.dc.html`) and render fully only inside the design tool they were made in — treat them as the source of truth for layout, styling, copy, and interaction, and **recreate them in the target environment**. No codebase exists yet: choose an appropriate stack (recommendation below) and implement there.

**Recommended stack** (no existing codebase): an offline-first **PWA** — React (or similar) + a local store (IndexedDB via e.g. Dexie/RxDB) syncing to a hosted backend (e.g. Supabase/Postgres: auth, row-level security, file storage). Installable to home screen; uses Geolocation API (with `watchPosition` + fix averaging) and camera via `<input capture>` / MediaDevices. PDF/Excel generation server-side or client-side. A read-mostly web portal shares the same backend.

## Fidelity
**High-fidelity.** Colors, type, spacing, radii, copy, and interactions are final intent — recreate pixel-perfectly (within the chosen component library's conventions). ## The 14 Screens
All screens live in `design/Phone.dc.html`; `design/Trials App.dc.html` mounts one phone per screen (ids 2a–2g, 3a–3g). Layout constants: app background `#F4F5F4`, content padding 14–16px, cards white with `1px solid #E4E4E6` border, radius 11–16px, bottom tab bar (Today · Assess · Map · Spray · Walk) with active tint `#E3F1EA` and green icon/label. Secondary screens (site, photos, storage, team, reports, setup, add) show a `‹ Today` back link instead of a highlighted tab. Minimum hit targets 44px.

1. **Login (3a)** — wordmark, email + password, primary Sign in, "Email me a sign-in link instead", role explainer, offline note. No tab bar. Auth: email/password + magic link; session persists offline.
2. **Today / Home (2a)** — GPS pill (`GPS ±4 m`, pulsing dot); "nearest trial" hero card (green 1.5px border) with distance eyebrow (`NEAREST · 40 M — YOU'RE STANDING IN IT`), status list (A sprayed ✓ / assessment open ! / B pending ○), primary Resume button, quick links (Site details · Photos · Reports · Team); sync-status row (tap → Storage); ALL TRIALS list with status chips; dashed "＋ Add a trial" button.
3. **Assess run (2b) — the deep flow.** Top GPS strip (green when on-order; burnt/amber variant when accuracy > 6 m: "GPS coarse — row check only"). Plot card: plot id in 32px mono, chips REP/ROW/POS, treatment name+product in green (hidden when Blind toggle on — black pill). Progress bar `n/72`. Measure chips (active = green tint + green 1.5px border) built from the trial's measure list; "Edit list" opens the measure picker (replaces pad): grouped pills — DISEASE (Stripe rust, Leaf rust, Septoria tritici, Yellow leaf spot, Powdery mildew, Net blotch, Scald — unit %), WEEDS (Annual ryegrass, Wild oats, Brome grass, Barley grass, Wild radish, Capeweed, Sowthistle, Fleabane — unit /m², cap 999), CROP (Phytotox %, Growth stage GS, Plants /m, Biomass %, Lodging %). Aux row: Photo (toggles count), Voice (pulses "Listening…", then fills first two measures and shows transcript line), Note. 3×4 number pad (52px cells, mono 21px; ⌫; last key cycles to next measure, green tint). Bottom: "Same as last" (copies previous plot's values for active measures) + primary "Save · {nextPlot} →" (advances along walk order, resets to first measure); "↩ back to {prev}" underneath. **Walk order**: serpentine by position — pos 1 rows 1→12, pos 2 rows 12→1, etc., skipping non-treatment cells.
4. **Spray map (2c)** — 12×8 grid of the real Matong layout (data in `fixtures/matong-trial.json`), rep band header (REP 1 = pos 1–2 green, REP 2 = pos 3–5, REP 3 = pos 6–8), row labels R1–R12. Cell states: treated (white, treatment number), assessed (fill `#DCEDE4`, text `#00623C`), A-only (green 2px inset bottom edge), OUT (`#F6DCD2`, ✕), skip (diagonal 45° stripes `#ECECEA`/`#E0E0DE`), spare (`#ECEDEC`, –), reserve (dashed grey border, R), marginal (dashed burnt border), issue (solid burnt 1.5px border), selected (2px black outline). Tap → sticky bottom sheet: plot id, meta, treatment + product, status lines (sprayed/B-due/assessed/issue/relabel/marginal), and "⚑ Log spray issue" (burnt outline button) which creates an open issue.
5. **Spray day (2d)** — segmented tabs **Mix / Order / Record / Issues** (badge with open count). Mix: info banner (1.5 L bottle per treatment, adjuvant last, <2 mL = syringe), progress `n / 24 MIXED`, checklist rows (circle check → green, row dims to 62% opacity) with per-batch mL recipes. Order: "water first" banner; rows `T{n} · name` + its 3 plot ids, A-ONLY chip where applicable, same check behavior. Record: 2-col grid of condition cards (Date, Start, Finish, Operator, Temp, RH, Wind, Nozzle, Pressure, Speed) — auto-filled from GPS + BOM at run start in the real app, editable.
6. **Spray issues (2e)** — burnt banner ("lands in the correction log"). Issue cards: plot id + type (burnt, 800 weight) + OPEN/FIXED chip; body text; timestamp/author in 10px mono. Open issues show fix actions: for a wrong-bottle issue — primary "Relabel {plot} as {applied trt} — as applied" and ghost "Exclude {plot} from analysis"; generic issues get "Mark resolved". Resolving: sets FIXED chip + green fix summary, appends a CORRECTION LOG entry (mono rows, e.g. `505 · was T14 → now T20 as applied · issue #1`), and — for relabel — updates the plot's effective treatment everywhere (map cell, assess header, exports flag original + corrected).
7. **Add a trial (2f)** — source cards: Spray map PDF / Protocol document (.docx) / Mixing plan (.xlsx) / ARM export / Start blank. Then parsing state (pulsing card), then parsed preview: trial name, chips (24 TREATMENTS / 3 REPS · RCB / 96 POSITIONS / 5 OUT · 2 MARGINAL / A+B TIMINGS), mini grid (9px cells: green=treated, burnt=OUT, grey=other), first treatments line, primary "Looks right — create trial" + ghost "Fix mapping first", then success card → "Next: map the site with GPS →" / "Later — open Today". Server-side parsing of the user's real documents (fixtures included) is a core feature.
8. **Site setup — GPS corner mapping (3b)** — Step 1: stand at front-left corner of Plot 101, phone averages ~30 s of fixes ("±2.8 m and tightening"), Mark corner A. Step 2: walk the front edge past pos 8, Mark corner B (shows corner A locked with coords ±1.9 m). Review: "GRID LAID FROM 2 CORNERS" chips (bearing, front edge length, rows, plot size) + mini grid + "pin the grid" / "re-mark". Success card. **Spec**: A→B vector = front edge bearing; plot polygons generated from trial spec (2×12 m plots); every plot gets a lat/lng footprint; locate = point-in-polygon with row-level confidence when accuracy exceeds plot width.
9. **Site details (3c)** — key/value cards: COOPERATOR (grower, property, phone, agronomist), PADDOCK & SOWING (crop/variety, sown date + rate, previous crop, soil + pH), FERTILISER & PADDOCK INPUTS (rows: product+rate, method, date chip; "＋ Add application" appends), SITE NOTES (free text). All feed the report's site page.
10. **Plot photos (3d)** — filter pills (All · n / Flagged · n), 3-col square-tile grid, each tile: placeholder image area, burnt flag dot when flagged, bottom overlay (rgba(20,20,20,.72)) with `plot · Tn` and date in mono. Storage note card: compressed ~300 KB on device, full-res upload on Wi-Fi, filed trial › plot › date, same plot across visits = timeline.
11. **Storage & sync (3e)** — queue card (burnt border) "WAITING FOR SIGNAL — 3 assessments · 21 photos (6.2 MB)" + "Sync now" → flips to green "ALL SYNCED — queue clear"; ON THIS PHONE stat grid (trials offline, scores DB, photos, last sync); RULES toggle rows (40×24 switch, green when on): Photos on Wi-Fi only / Keep every trial offline / Nightly backup; explainer: portal keeps the master copy, phones are disposable, backups kept 12 months. **Sync spec**: writes hit local store first (<100 ms), background sync with per-record status; conflicts resolved last-write-wins per field with full audit history; photos queue separately.
12. **Team & access (3f)** — people rows (avatar initials, name, scope line, role chip): ADMIN (green), TEAM, GROWER (grey), LIMITED (burnt tint). Burnt explainer card of rep limitations. NEW LOGIN block: role pills (Admin / Assessor / Grower / Chem rep · limited) with per-role description, email field, "Send invite link" → confirmation ("expires in 7 days · you approve the first sign-in").
13. **Reports & export (3g)** — "Blind codes on rep copies" toggle; RANKED CONTROL preview card (sorted descending bars, green fill, SAMPLE DATA chip; labels become T-codes when blind toggle on); output cards: Client PDF report (cover · site + conditions · means table · ranked chart · photo pages) with Generate action → queued confirmation; Excel/ARM export (plot-level, one tab per assessment — must match the format of `fixtures/Junee_Field_Assessment.xlsx`); Field-day handout (one page, Rep 1 walk order).
14. **Field-day walk (2g)** — green GPS line ("You're at Row n · Pos n ✓"), big stop card (STOP n OF 24, plot id, treatment name 26px/800, product), severity comparison bars (this treatment green vs untreated grey, values in mono), green result strip ("nn% control vs untreated (mean of 3 reps)"; untreated shows "This is the check…"), caution line ("quote treatment means, not this plot"), large Prev/Next buttons. Walk order = Rep 1: pos 1 rows 1→12 (treatments 1–12), then pos 2 rows 12→1 (24…13).

## Interactions & Behavior (cross-cutting)
- **GPS model** (user's chosen behavior): the app never forces plot assignment from GPS. Assessment auto-advances along the walk order; GPS *verifies* (row-level check) and warns on mismatch. Accuracy ≤6 m → green "on walk order"; >6 m → amber "row check only". Nearest-trial detection on Today from site corner geofences.
- **Blind scoring** is toggleable any time (per user, per trial); hides treatment name/product during scoring.
- Buttons: primary = `#007749` bg / white text / radius 11–12px / weight 700; ghost = white bg, `1.5px solid #D6D7D6`; destructive/flag = burnt outline. Checklist checks animate to green circle. Toggles slide 150ms.
- All flash/confirmation strips: `#E3F1EA` bg, `#00623C` text, radius 8px.
- Everything works offline; every mutation is queued (see Storage spec above).

## State Management (entities)
`Org` → `User` (role: admin | assessor | grower | rep; scope: trial ids) → `Invite`.
`Trial` (name, site, crop, design RCB, reps, plot size, water rate, timings A/B, measures[], status) → `Site` (corners lat/lng, bearing, cooperator, paddock/sowing, fertiliserApplications[], notes) → `PlotCell` (row, pos, rep, kind: treatment n | out | skip | spare | reserve; marginal flag; polygon) → `Treatment` (number, name, products + rates, timings, aOnly) → `MixBatch` (per-batch recipe, mixed flag, who/when) → `SprayRun` (timing, conditions record, order progress) → `Issue` (plot, type, text, status, fix, author, ts) → `CorrectionLogEntry` (plot, was, now, source) → `Assessment` (timing window label e.g. "14–28 DAA", measures) → `Score` (plot × measure, value, assessor, ts) → `Photo` (plot, assessment, flagged, geotag) → `SyncQueueItem`.
The wrong-plot fix mutates: Issue → fixed; CorrectionLog append; PlotCell.effectiveTreatment (original preserved).
